## 反爬的本质

反爬不是要完全阻止爬虫——这做不到。反爬的目的是**提高爬虫的成本**，让爬取变得不划算。

## 常见反爬策略及应对

### 1. User-Agent 检测

网站检查请求头中的 User-Agent，拒绝非浏览器的请求。

**应对**：设置合理的 UA
```python
headers = {
    "User-Agent": "Mozilla/5.0 (Windows NT 10.0; Win64; x64) "
                  "AppleWebKit/537.36 (KHTML, like Gecko) "
                  "Chrome/120.0.0.0 Safari/537.36"
}
```

### 2. IP 频率限制

同一 IP 短时间内请求过多 → 封 IP。

**应对**：
- 降低请求频率（加 `DOWNLOAD_DELAY`）
- 使用代理 IP 池
- Scrapy 中设置：
  ```python
  # settings.py
  DOWNLOAD_DELAY = 2  # 每次请求间隔2秒
  RANDOMIZE_DOWNLOAD_DELAY = True  # 加随机抖动
  ```

### 3. Cookie / Session 验证

需要登录或维持会话状态。

**应对**：携带 Cookie，必要时模拟登录
```python
# Scrapy 自动管理 Cookie
COOKIES_ENABLED = True

# 或手动设置
headers = {"Cookie": "session_id=xxx"}
```

### 4. 验证码

滑块、点击、数字/字母验证码。

**应对策略（由易到难）**：
- 简单的数字验证码：OCR 识别（tesserocr 库）
- 滑块验证：selenium 模拟滑动轨迹（加随机抖动模拟人类）
- 复杂验证码：接打码平台（2captcha、超级鹰）
- 最好的策略：**降低频率到不会触发验证码的程度**

### 5. JS 动态渲染

数据通过 JS 异步加载，直接请求 HTML 拿不到。

**应对**：
- **方案1**：找 API——浏览器 F12 → Network → XHR，直接调接口
- **方案2**：Selenium / Playwright 模拟浏览器
- **方案3**：分析 JS 逻辑，逆向出 API 签名规则

> 方案1永远优先——又快又稳。只有找不到API时再考虑方案2/3。

### 6. 请求参数加密

URL 参数或 POST body 被加密/签名。

**应对**：
- 在 JS 源码中搜索关键参数名
- 找到加密函数后，用 Python 重写或用 `execjs` 调用
- 实在是复杂的：直接用 Selenium 绕过去

### 7. 字体反爬

页面显示正常，但源代码中的数字是乱码——使用了自定义字体映射。

**应对**：
- 下载 `.woff` / `.ttf` 字体文件
- 用 `fontTools` 库解析字体映射关系
- 建立字符到真实数字的映射表

## 降低被封概率的通用原则

1. **尊重 robots.txt**（但不要完全相信它）
2. **请求间隔**：至少 1-2 秒，人类不会在 0.1 秒内连续点击
3. **随机化**：UA、延迟时间、请求顺序都加随机
4. **不要在工作时间高频率爬**：凌晨2-6点是"友好时段"
5. **使用 Referer**：伪造从搜索引擎或站内页面跳转过来的来源
6. **每次只爬需要的页面**：不要无脑遍历

## 法律与道德警告

- ✅ 公开数据的合理采集
- ✅ 用于个人学习/研究
- ⚠️ 爬取速度过快导致对方服务器压力
- ❌ 爬取用户隐私数据
- ❌ 破解付费内容
- ❌ 违反网站 ToS（服务条款）
