## 什么是 Web 安全

Web 安全关注的是保护 Web 应用程序免受攻击和未授权访问。它涉及**客户端、服务器、传输过程**三个环节。

## CIA 三元组

信息安全的核心模型，是所有安全策略的基础：

| 要素 | 含义 | 例子 |
|------|------|------|
| **机密性 (Confidentiality)** | 数据不被未授权访问 | 密码加密存储、HTTPS传输 |
| **完整性 (Integrity)** | 数据不被篡改 | 数字签名、哈希校验 |
| **可用性 (Availability)** | 服务在需要时可访问 | DDoS防护、冗余备份 |

## 常见的攻击面

攻击面 = 攻击者能尝试入侵的所有入口点：

1. **输入框**——登录、搜索、评论、文件上传
2. **URL 参数**——GET 请求中的查询字符串
3. **Cookie / Session**——会话令牌窃取
4. **API 接口**——未鉴权的后端接口
5. **第三方依赖**——供应链攻击
6. **错误信息**——泄露堆栈跟踪和系统信息
7. **人为因素**——弱密码、点击钓鱼链接

## 纵深防御（Defense in Depth）

单一防线必被突破。纵深防御意味着多层安全机制：

```
第1层：网络防火墙
第2层：WAF（Web应用防火墙）
第3层：输入验证 + 参数化查询
第4层：加密存储 + 最小权限
第5层：日志监控 + 异常告警
```

> 原则：**永远不要相信用户的输入**。这是所有Web安全问题的根源。

## OWASP Top 10

OWASP（开放Web应用程序安全项目）定期发布最严重的10大Web安全风险：

1. 访问控制失效
2. 加密失败
3. **注入攻击**（SQL注入、命令注入）
4. 不安全的设计
5. 安全配置错误
6. 易受攻击的组件
7. 认证失效
8. 软件和数据完整性失效
9. 安全日志和监控失效
10. **服务端请求伪造 (SSRF)**

> 本文系列将重点讲解其中最常见和重要的几种攻击类型。

## 安全开发的基本原则

1. **最小权限**：代码/服务只给必要的权限
2. **默认安全**：不安全选项需要主动开启
3. **深度防御**：不依赖单一安全机制
4. **不信任输入**：所有输入都要验证和净化
5. **安全的失败**：出错时不要泄露信息
